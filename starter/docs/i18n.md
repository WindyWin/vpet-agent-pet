# Translations

Agent Pet speaks English and Vietnamese. English is the source language: every
user-visible string is written in English in the code and wrapped for Qt Linguist.
`translations/agent-pet_vi.ts` holds the Vietnamese text. The build compiles it to
`agent-pet_vi.qm` and embeds that in the `agent-pet` and `agent-pet-updater` binaries,
under `:/i18n/`. There is nothing to download or install separately. See
[ADR 0022](adr/0022-localization.md) for how the language is chosen
and switched while the pet runs.

## What is translated

- The pet window, its menus, the tray, the alert bubble, notes and the session list
- The settings, preview and about dialogs
- The pet's speech: recap, wellness reminders, easter eggs and bedtime notes
- Alert titles and statuses
- Integration, start-at-login, focus and update messages shown in the interface
- The updater helper's result, which the pet shows after an update
- The `.desktop` entry's `GenericName[vi]` and `Comment[vi]`, and `CFBundleLocalizations` in the
  macOS `Info.plist`

The following stay in English: command-line output and `--help`, the hook (it prints
nothing), the installer's prompts, documentation, license texts, log warnings and
developer details such as catalog validation errors and the preview's timing line. Text
the pet writes to disk stays in English too: `recap.json` stores "Unknown project",
and that is translated only when it is shown.

## Workflow

After changing user-visible text in `src/`:

```bash
cmake --build build --target update_translations   # rewrites translations/*.ts from the sources
python3 scripts/check_translations.py               # compares with the committed .ts (CI runs this)
```

Translate the new entries, either with Qt Linguist (`linguist6 translations/agent-pet_vi.ts`)
or by editing the XML, and remove the `type="unfinished"` attribute from each one you
translate. Commit the `.ts` file with the code. An unfinished entry shows English,
so a missing translation never breaks the app. CI fails if the committed `.ts` lists
strings that differ from the sources. The `i18n` test checks that every finished
translation keeps its source's `%1`…`%9` and `%n` markers, keeps any `&` mnemonic
(at most one), and is not empty.

`lupdate` runs with `-locations none`, so line moves alone do not touch the `.ts`.
It scans every file under `src/`, including the macOS sources, so the result is the
same on every platform.

## Conventions

- **Where `tr()` comes from.** In a `QObject` class, use the class's `tr()`; its
  context is the class name, for example `pet::PetWindow`. Code outside a QObject
  uses a context from `src/i18n/contexts.h`: `Alerts`, `Pet` (the pet's own speech),
  `Updater`, `Integrations`, `Startup`, `Focus` and `Settings`. These need only QtCore,
  so headless code can use them. Without a translator, `tr()` returns the English
  source.
- **Placeholders.** Use `tr("Installed version: %1").arg(version)`. Never build
  sentences by concatenating pieces, because word order changes between languages.
  Give the translator the whole sentence.
- **Plurals.** There is no English `.qm`, so `%n` would show "turn(s)". Write the
  singular and plural as two strings:
  `n == 1 ? tr("1 turn") : tr("%1 turns").arg(n)`. Vietnamese uses one form for both.
  For a table of strings passed to a helper, mark them with
  `QT_TRANSLATE_NOOP("Pet", "…")` and translate them where they are used.
- **Translator notes.** Put `//: note` on the line before a `tr()` call when the
  string is ambiguous: where it appears, what `%1` is, or its length limit.
- **Mnemonics.** Keep the `&` in a translation, on a letter of the translated word.
- **Standard buttons.** Qt does not ship a Vietnamese translation of its own dialogs.
  Give buttons explicit `tr()` text, such as `button->setText(tr("Close"))` or custom
  `QMessageBox` buttons, instead of relying on `QDialogButtonBox` or the default
  Yes/No labels.
- **Live switching.** Text is set when a widget is built and again in its
  `retranslate()`, which `changeEvent(QEvent::LanguageChange)` calls. Text the
  `Monitor` refreshes every 250 ms (bubble, tray, session list) needs nothing more.
  Dialogs are built in one go, so an open one (settings, preview, About, updates)
  closes and reopens at the same place; settings come back on the same tab. A note on
  screen was worded in the old language and goes away; the eye-break countdown says
  its next second in the new one.

## Vietnamese voice

The pet speaks as "em" and calls the user "bạn", with a light, friendly tone
("Uống chút nước nào bạn ơi 💧"). Interface labels (menus, settings, buttons) are
plain and neutral, like other Vietnamese desktop software. Keep this split when you
add strings: only the `Pet` context speaks in the pet's voice.

## Adding a language

1. Add `translations/agent-pet_<code>.ts` to `pet_ts_files` in `CMakeLists.txt` and
   run `update_translations` to create it.
2. Add the language to `i18n::Language`, `fromName`, `name`, `resolve` and `install`
   in `src/i18n/language.cpp`, and to the Language combo in the General settings tab.
   The combo lists each language's name in that language.
3. Add `GenericName[<code>]` and `Comment[<code>]` to `packaging/agent-pet.desktop.in`,
   and the code to `CFBundleLocalizations` in `scripts/package_macos.py`.
4. Extend `tests/i18n_tests.cpp` (`resolve` and the marker check, which reads one `.ts`).

## Future work

- A tone setting for the pet's voice, or generated conversation. The `Pet` context
  already separates the pet's speech from interface labels, so either can replace
  that context alone.
- If more languages make the binaries noticeably larger, the `.qm` files can move to a
  separate `translations.rcc` next to `artwork.rcc`, so updates can reuse it unchanged.

# 0029. Cues: events decoupled from how a pet shows them

- Status: Accepted
- Date: 2026-10-08

## Context

Events reached the pet as animation names (#64). `sessionAnimation()` renamed five session states to
state names, `Monitor` read `Player` details (a `closing` request, touch and ambient resting, the snack
pool), `PetWindow` selected `starting`, `closing`, `angry` and `closing_angry`, `Ambient` selected
`sleeping`, and `Mood`, `EasterEggs` and `Monitor` named reaction pools such as `turn_finished`,
`long_turn` and `eye_break`. [0028](0028-pet-packs.md) gathered the state names into
`core-states.json` and marked it provisional: every pet had to define those 14 states, so a new
character could not answer an event its own way.

## Decision

- Event code raises **cues**, named in one vocabulary file, `src/animation/cues.json`, which replaces
  `core-states.json` and is embedded into the build. A cue is either:
  - a **state cue**, which plays one state with a required playback shape. Its default state is
    today's (`attention` → `needs_input`, `quit` → `closing`, `drag` → `dragging`, …). Session states
    are state cues of the same name, so `sessionAnimation()` is gone. Lifecycle cues are `start`,
    `quit`, `annoyed` (pestered into leaving) and `quit-angry`; `nap` is the ambient doze.
  - a **reaction cue** (`celebrate`, `snack`, `milestone`, `long-turn`, `birthday`, `danger`,
    `eye-break`, …), which draws a state from a weighted pool. A pet without a pool for it plays
    nothing, as before.
- The mapping is app defaults plus per-pet overrides. A catalog's `cues` section maps a state cue to
  another state, or a reaction cue to its pool. It replaces the `reactions` section, so the catalog
  schema is now 2. `Catalog::load` rejects a name outside the vocabulary, a state it does not have,
  a remapped `idle` cue (the catalog format's rest state) and a pool that does not end by itself.
- The contract between the app and a pet is now "every state cue plays an existing state of its
  shape" (`Catalog::contractError()`). The drag state may not be shared with another state cue,
  because the player never resumes into it. `PetLibrary::activate` refuses a pet that breaks this.
- `Player::play(cue)`, `stateFor(cue)`, `requested(cue)` and `pool(cue)` are the mapping's API. Event
  code tracks cues, so pets may share states between cues: `PetWindow` follows the quit cue it played,
  not the state name.
- Decisions that peeked at animation state get explicit inputs: `PetWindow::quitting()` and
  `PetWindow::resting()` for `Monitor`, and `Mood::celebrate()` returns the cue it drew from, so the
  water reminder is skipped only after a `snack` cue.
- Urgency stays on the event side: `Monitor` decides which cues interrupt.
- `scripts/migrate_catalog.py` moves a schema 1 catalog's reactions into `cues` under the new names.
  It migrated VPet and the test fixtures; a schema 1 catalog is refused with a message naming it.
  `scripts/new_pet.py` now scaffolds one state per playback shape (`idle`, `busy`, `hello`, `oops`,
  `bye`, plus `held` for dragging) and maps every state cue onto them.
- Touch regions, falls, edges, moves, activity decoration, fidgets and mood art keep their own catalog
  sections, which already belong to each pet.

## Consequences

- A new character can answer `attention`, `turn-finished` or any other cue with its own states, and a
  minimal pet needs six states instead of fourteen. VPet's catalog changes only in its reaction names,
  so it plays exactly as before; only the index (`artwork.rcc`) changes in an update, no sequence pack.
- Adding a cue is one line in `cues.json`, a default state or none, and the event code that raises it.
  Plugin packs' custom events (#43) can become reaction cues.
- Pool, occasion and reminder names in the code and tests now use hyphens (`late-night`,
  `leave-work`), matching the session state `turn-finished`.
- `--state` and the developer States menu still name states directly.

## Validation

### Cue mapping evidence — 2026-10-08

- Ubuntu 24.04, Qt 6.4.2 (the CI's Qt 6.5.3 could not be downloaded in that environment, so the
  version check and one `QDataStream::Qt_6_5` use were relaxed locally, not in the tree), GCC 13,
  CMake 3.28: `ctest --test-dir build` passed all 14 tests. `pets` covers the vocabulary file, the
  mapping (defaults, overrides, unknown names, shapes, a shared drag state, schema 1 refused) and
  plays every cue on the scaffold-shaped `mini` fixture, on `duo` and on VPet. `prototype` asserts
  that every session aggregate is a state cue that plays, and that celebrations report their cue.
- `scripts/check_new_pet.py` checks that the scaffold maps every state cue to a state of its shape
  and still reproduces the `mini` fixture; `verify_assets.py` reported `OK: vpet (141 sequences).`
- Open: macOS and Windows CI runs.
